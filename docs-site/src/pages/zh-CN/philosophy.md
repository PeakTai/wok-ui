# 设计哲学

## 实用主义

wok-ui 的设计核心只有一个：**实用主义**。不追求技术的新潮，也不追求 API 的丰富，而是追求**用最少的概念、最直观的方式解决实际问题**。

### 简洁直观

好的框架应该让开发者**一眼就能看懂代码在做什么**，而不是需要理解一堆抽象概念后才能上手。

wok-ui 坚持**只有一种正确的方式做一件事**，没有多种写法之间的纠结，也没有"该用哪个 API"的选择负担。你写的代码就是最终执行的逻辑，没有隐藏的编译步骤，也没有隐式的框架行为。

### 面向对象的字面量构建

wok-ui 的模块是类，DOM 结构通过字面量对象描述：

```ts
this.addChild({
  classNames: 'card',
  children: [
    { tag: 'h3', innerText: '标题' },
    16, // 间隙
    { tag: 'p', innerText: '内容' }
  ]
})
```

这种写法有几个特点：

- **代码即结构**：你看到的就是 DOM 树，不需要在模板、脚本、样式之间切换
- **类型安全**：TypeScript 类型约束贯穿始终，IDE 提示即文档
- **无编译魔法**：写的就是最终执行的代码，没有额外的转换步骤，也没有响应式代理

### 显式优于隐式

wok-ui 不相信"魔法"。状态变了？调用 `render()`。模块不要了？调用 `destroy()`。需要缓存？用 `cacheModule()` 显式声明。

这种显式设计意味着：

- 状态何时更新、界面何时刷新，由你调用 `render()` 的时机决定
- 模块何时被挂载、何时被销毁，由 `mount()` 和 `destroy()` 明确定义
- 所有行为的来源都是你写的代码，没有额外的隐式规则

代价是多写几行代码，收益是**行为完全可预测**。

## AI 编程优势

wok-ui 的设计哲学恰好与当前 AI 代码生成的工作方式高度契合。

### 为什么 wok-ui 适合 AI 编程

#### 1. 概念少，选择少

AI 生成代码是基于概率的预测。框架的概念越多、选择越多，AI 出错的概率就越高。

wok-ui 对同一件事只提供一种做法：

| 场景       | wok-ui 的做法                              |
| :--------- | :----------------------------------------- |
| 响应式数据 | 直接修改属性，调用 `render()`              |
| 条件渲染   | 回调函数 `add => { if (x) add(...) }`      |
| 生命周期   | `mount()` / `destroy()`                    |

没有并存的多套 API，也没有"该用哪种写法"的负担，**唯一路径就是正确路径**。

#### 2. 无隐式规则

wok-ui 没有"你必须知道但框架不会告诉你"的规则。所有约束都是显式的、类型化的、运行时可验证的。

#### 3. Token 效率高

同样的功能，wok-ui 用更少的 token 表达：

```ts
// wok-ui: ~15 tokens
new Button({ text: '确认', type: 'primary', onClick: submit })
```

更少的代码意味着：

- AI 生成更快
- 上下文窗口能容纳更多业务逻辑
- 修复错误时消耗的 token 更少

#### 4. 错误直观可修复

wok-ui 的常见错误都是显式的遗漏，比如忘记调用 `render()`、忘记复用模块，补上即可。

这类错误不需要理解框架内部机制，因为框架没有内部机制——代码就是行为。

### 适用场景

wok-ui 特别适合以下 AI 辅助编程场景：

- **快速原型开发**：AI 生成大量 CRUD 页面，wok-ui 的简洁 API 让生成质量更稳定
- **内部管理系统**：表单、表格、弹窗是核心，wok-ui 内置模块直接覆盖
- **低代码/无代码平台**：字面量构建 DOM 的方式天然适合可视化配置转代码
- **AI 代码助手集成**：作为知识库中的"推荐框架"，减少 AI 的决策点和错误率

### 总结

wok-ui 的实用主义设计，让它在各种规模的项目中都能胜任：

- **轻量易维护**：概念少、无第三方依赖，即使项目长期迭代，维护成本依然很低，已有大量基于 wok-ui 长期维护的项目
- **细节经得起打磨**：内置组件虽然基础，但交互、响应式与类型约束等细节都经过精细打磨，足以支撑企业级应用
- **对 AI 编程友好**：单一做法、无隐式规则、代码即行为，人类开发者和 AI 编程助手都能稳定地产出高质量代码
- **行为可预测**：渲染与生命周期完全显式，长期演进与多人协作都更可控

无论是快速验证一个想法，还是构建需要长期维护的企业级系统，wok-ui 都是一个高效可靠的选择。
